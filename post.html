POST poruka

Dijagnoza, interpretacija i rješavanje grešaka pri pokretanju računala

Što je POST i što provjerava?

🔍 Definicija

POST (Power-On Self Test) — automatski test koji firmware (BIOS/UEFI) provodi svaki put pri uključivanju, prije učitavanja OS-a.

⏱️ Trajanje

Legacy BIOS: 2–8 s · UEFI s Fast Boot: 0,5–2 s · UEFI bez Fast Boot: 3–6 s

✅ Uspješan POST

1× kratki beep (AMI) ili bez zvuka (Award/UEFI) → kontrola predana boot manageru.

🔧 7 faza POST provjere
1CPU i registri procesora
2ROM BIOS/UEFI firmware provjera
3Memorijski kontroler i RAM test
4Grafička kartica — video signal
5Sistemski tajmer i DMA kontroleri
6Tipkovnica, miš, I/O uređaji
7Diskovi — SATA/NVMe uređaji

„Računalo se ne uključuje — crni ekran, nema zvuka"

Simptomi:
✗ Ventilatori se ne vrte
✗ LED na kućištu ne svijetle
✗ Nema beep signala
✗ Ekran ostaje crn

  2. Predložite redoslijed provjere
  3. Koje alate koristite?
  4. Kada pozivate servis?
🔍 Dijagnostički tijek (rješenje)
Korak 1Provjeri kabel napajanja i utičnicu multimetrom (230V)
Korak 2Testiraj PSU paperclip testom (zelena + crna žica 24-pina)
Korak 3Minimalna konfiguracija — izvadi RAM, GPU, sve osim CPU+PSU
Korak 4Provjeri 24-pin i 8-pin CPU konektore na matičnoj ploči
ZaključakNajčešće: mrtvi PSU (~60%), kratki spoj (~25%), CPU (~15%)

„Neprekidni beep signal, nema slike na monitoru"

Simptomi:
✓ Ventilatori vrte normalno
✓ LED — napajanje OK
✗ Ekran: crn / nema signala
✗ Neprekidni beep (AMI BIOS)
! Nedavno dodan novi RAM modul
🔬 Analiza beep koda

AMI BIOS neprekidni beep = memorija nije prepoznata ili nema kontakta u slotu. Fatal error — POST se ne može nastaviti.

🛠️ Postupak rješavanja
1. Fizička provjera
Ugasi PC · izvadi RAM · provjeri kontakte · očisti gumicom
2. Resetiraj slot
Probaj u drugi slot (A1→A2) · testiraj samo jedan modul
3. Kompatibilnost
DDR4 vs DDR5 · SPD podaci · QVL lista matične ploče
⚠️ Čest propust učenika
Miješanje DDR generacija ili brzina bez XMP profila

„UEFI POST poruka: No Boot Device Found"

POST poruka (UEFI):
✓ POST OK — svi testovi prolaze
✓ RAM: 16GB DDR4 — OK
✗ Reboot and Select proper Boot device
✗ or Insert Boot Media in selected Boot device
! Windows 10 instaliran, disk nije fizički oštećen
🔍 Mogući uzroci
1. Boot Order — disk nije na vrhu liste
2. Bootloader oštećen (MBR/EFI)
3. SATA kabel / NVMe nije prepoznat
4. Secure Boot / CSM konflikt
□ Provjera Boot Order-a u UEFI
□ Provjera SATA/NVMe konektora fizički
□ Pokretanje Windows Recovery USB-a
□ bootrec /fixmbr ili bcdboot
□ Provjera CSM / Secure Boot postavki

„Računalo se gasi nakon 3–5 minuta rada"

Simptomi i okolnosti:
✓ POST prolazi bez greške
✓ Windows se učitava normalno
! Nakon 3–5 min: naglo isključivanje
! UEFI log: CPU temp = 98°C
! Throttling vidljiv u Task Manageru
🔥 Termalni shutdown

UEFI šalje ACPI signal za hitno isključivanje kad CPU premaši TJmax (Intel: 100°C, AMD: 95°C) kako bi spriječio fizičko oštećenje čipa.

📊 Referentne temperature CPU-a
Idle
30–45°C
Load
65–75°C
Upozorenje
85–90°C
Kritično
95°C+
Uzroci: istrošena termalna pasta (svake 2–3 god.), začepljeni hladnjak, pokvareni ventilator, loše postavljen hladnjak (bez paste).

„Secure Boot violation — OS blokiran"

POST poruka (UEFI Secure Boot):
✓ Hardware init — OK
✓ Memory test — 8192 MB OK
✗ Secure Boot Violation!
✗ Invalid signature detected.
! Korisnik instalirao Linux uz Windows (dual-boot)
🔐 Zašto se ovo događa?

Secure Boot provjerava digitalni potpis bootloadera. Stariji Linux bez shim sloja nije potpisan Microsoft ključem → UEFI odbija pokretanje.

🛠️ Rješenja po prioritetu
Opcija 1Shim bootloader (Ubuntu/Fedora automatski) — radi sa Secure Boot
Opcija 2Ugasi Secure Boot: UEFI Security → Disabled (rizik: smanjena sigurnost)
Opcija 3MOK (Machine Owner Key) — ručno potpiši bootloader vlastitim ključem
📋 Diskusijsko pitanje: Koja je opcija sigurnija? Kada je opravdano ugasiti Secure Boot?
